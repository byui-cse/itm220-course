1. Choose one user story

Complete this sentence:

A person using my database should be able to [action] so that they can [reason].

Keep the action to one new row in one table. Examples: add an event so members can see it; add a reservation so a business can track it; add an item so it appears in a collection.

For your first insert, choose a parent table if you can. A parent table has no foreign keys that need to point to another table. In the Puppies database, breed or kennel are examples. If you choose a child table such as puppy, plan how the app will provide every required foreign key so the new row connects to existing parent rows. For example, the app could let a person choose a breed or kennel by its readable name, then use the matching key in the insert—not ask the person to guess an ID.

When it is reasonable, use a join in the list query so people see a readable related value. If that makes your first app too difficult, show the inserted table clearly and let the filtering query demonstrate a relationship instead.
